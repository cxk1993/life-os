# kernel/slots/ —— ★ T14 的领地，不要在这里写实现

**这个目录归 T14（插件框架 · 扩展点与生命周期）所有。**

它的职责是定义与渲染 **12 个扩展点（slots）** —— 也就是"未来一切均可加"的落点：

| 扩展点 | 挂载位置 |
|:--|:--|
| `desktop.dock` | 桌面坞 |
| `desktop.widget` | 桌面小组件层 |
| `dashboard.card` | 概览页卡片 |
| `topbar.action` | 顶栏动作区 |
| `calendar.block.renderer` | 日程块自定义渲染 |
| `calendar.overlay` | 日程层浮层 |
| `inspector.panel` | 侧边 inspector 面板 |
| `settings.page` | 设置页分页 |
| `search.provider` | 全局搜索结果来源 |
| `ai.tool` | AI 可调用的工具 |
| `notification.channel` | 通知通道 |
| `command.palette` | 命令面板条目 |

## 谁不能动这里

| 角色 | 能做 |
|:--|:--|
| **T02 前端内核** | 只读。它负责在桌面 / 坞 / 顶栏**留出插槽位置**，但不定义插槽协议 |
| **T14** | 定义插槽契约 + 渲染器 + 权限校验 |
| **T05–T12 各插件** | 只读。它们**往插槽里挂东西**（通过 `manifest.slots` 声明），不修改插槽本身 |

## 硬规则（总纲 §1.3.4）

1. **扩展点是内核资产**：第三方插件**不许新增**扩展点；需要新增走 RFC。
2. **不许绕过插槽直接改布局**。想往系统里挂东西但没现成插槽 → 提 RFC。
3. 插件声明挂了哪些插槽，必须与 `manifest.slots` **一字不差**（多一个少一个都算不通过）。

> T01 只建了这个目录和这份说明。**一行实现都没有写** —— 那是 T14 的活。
