# CRUD 契约规范 · v1（插件通用增删改查）

> **提出**：workbuddy（云昔）· U2 数据侧同族（令 60 派工：calendar 编辑 + CRUD 契约规范）
> **时间**：2026-09-24 ｜ **状态**：v1 草案（候 todo/calendar/docs-diary/MiMo 四方与总监评议）
> **目的**：令 60 痛点 ——「todo 缺编辑入口，其他插件可能类似」。**四插件各写各的会出四套口径**；先定统一契约，各自实现，汇合时零返工。

---

## 1. 端点形（REST 惯例，与 todo 现状对齐）

| 操作 | 端点 | 说明 |
|:--|:--|:--|
| 列表 | `GET /api/v1/<id>/items` | 支持 `?limit=&offset=` 分页（默认 50） |
| 创建 | `POST /api/v1/<id>/items` | body 为下 §2 形状（不含 id） |
| 读取 | `GET /api/v1/<id>/items/{id}` | 404 = 不存在 |
| 更新 | `PATCH /api/v1/<id>/items/{id}` | **部分更新**（只传要改的字段） |
| 删除 | `DELETE /api/v1/<id>/items/{id}` | 204 |

- **鉴权**：全部走既有 Bearer（不新增免鉴权通道）
- **错误**：RFC7807（`application/problem+json`，内核已统一格式）

## 2. 条目形状（统一字段）

```jsonc
{
  "id": "t1",                    // 服务端生成，不可改
  "created_at": "2026-09-24T08:00:00Z",   // UTC ISO8601
  "updated_at": "2026-09-24T09:00:00Z",
  "version": 3,                  // 可选：乐观锁（每次更新 +1，PATCH 带 If-Match 校验）
  // ……插件自有业务字段（text/due_at/priority 等）平铺在此
}
```

## 3. ★ 交互层三态（H4 教训的规范化）

**每个写操作在 UI 上必须三态可区分**（缺一 = 静默失败）：

| 态 | 触发 | UI 要求 |
|:--|:--|:--|
| **加载中** | 请求飞行中 | 禁用提交按钮 + loading 指示 |
| **失败** | 4xx/5xx/网络错 | ★ **必须渲染错误**（`role="alert"`），写操作回滚（React Query `onError`） |
| **成功** | 2xx | 列表即时反映（乐观更新或 refetch） |

> 判例：todo QuickAdd 曾"失败但无提示"（H4）—— **本规范把"失败可见"升为契约条款**。

## 4. 编辑入口判据（令 60 主人痛点）

每个插件**至少满足**：
1. 列表页每条 item 有**编辑入口**（点条目或行内按钮 → 表单/抽屉）
2. 表单含**该插件全部用户可改字段**（字段清单由属主列）
3. 删除有**确认**（防误触）+ 成功/失败反馈
4. **空态**（无数据）与**错误态**（加载失败）视觉可区分

## 5. 归属与汇合

| 插件 | 现状 | 待做 | 属主 |
|:--|:--|:--|:--|
| `todo` | ✅ CRUD 齐全（含 QuickAdd NL） | 按规范对齐字段命名 | 豆包 |
| `calendar` | **缺编辑入口**（令 60 痛点） | **PATCH + 前端编辑表单** | calendar 属主（候认领） |
| `docs`/`diary` | 知默 docs 编辑链在制 | 后端 update audit | 知默 |

**P0 汇合**：各插件编辑入口完工 → 汐瑶 Playwright 全链联调 → 收编下一批。

v1 最小集。**乐观锁（version/If-Match）与批量端点**候 v2（先让四插件编辑入口跑起来）。

## 7. ★ 用户侧自定义（v1.1 补 · 主人「高度自定义化」要求）

**服务端契约只管"数据怎么存取"，视图侧必须把"看成什么样"还给用户** —— 下列四条为**插件视图的自定义底线**（各 CRUD 插件通用）：

| 项 | 要求 | 存储 |
|:--|:--|:--|
| **列显隐** | 列表的每个字段可由用户隐藏/显示 | localStorage（与内核 `ui.*` 同钥匙族）|
| **排序** | 列表可按任一用户可见字段排序（升/降），选择可被记住 | 同上 |
| **每页条数** | 用户可选（默认 50，候选项 20/50/100） | 同上 |
| **默认视图** | 用户可设定"进入插件时的默认排序/筛选" | 同上 |

**判据**：用户改过任一设置后，**刷新与重进都保持**（与 U1 收放、U3 侧栏同族的"折叠持久化"纪律）。

**纪律**：
- 自定义项**不得改变服务端语义**（只是视图参数）；
- 用户重置入口必须存在（"恢复默认"）；
- **新插件照抄本节**即可，不需要各自设计（先规范后实现）。
