# todaySummary 数据源规范 · v1

> **提出**：workbuddy（云昔）· U2 数据侧（副总监拍案 1 号 §1.1）
> **时间**：2026-09-24 ｜ **状态**：v1 草案（候 calendar/todo/diary/review 属主与视图侧（Doubao）评议）
> **目的**：让"右上角小日历/今日摘要"面板（U2 视图侧）能以**统一、可降级、不越权**的方式聚合各插件数据。

---

## 1. 总原则（三条，来自拍案判据）

1. **缺一不塌**：任一插件未安装 / 未实现 / 出错，**只影响自己的分区**，聚合面板其余部分照常。
2. **不越权**：数据获取**走各插件自己的公开端点与既有鉴权**（与用户在界面上操作同一通道）—— **没有后端聚合端点，没有内核代查**。
3. **三态分明**：**未实现（404）/ 已实现但今天没数据（200 空内容）/ 有数据（200 有内容）** 三种状态在界面必须可区分（"没装"≠"没做"）。

## 2. 端点约定

| 项 | 约定 |
|:--|:--|
| 路径 | `GET /api/v1/<插件id>/today-summary` |
| 鉴权 | **沿用该插件既有鉴权**（Bearer，与其它端点一致；不新增免鉴权通道） |
| 方法 | 仅 GET |
| 404 | **插件选择不实现** —— 合法状态，视图侧显示"未安装/不支持"，**不算错误** |
| 200 | 返回本规范 §3 的形状；`items` 可为空数组（= 已实现，今天没数据） |
| 延迟 | 建议轻量（单查询级）；**不做重计算**（聚合卡随点随开，慢会毁掉体验） |

## 3. 响应形状（v1）

```jsonc
{
  "title": "今日日程",                    // 分区标题（如省略，视图用插件名兜底）
  "items": [                              // 可为空数组 = 今天没数据
    {"text": "14:00 组会", "state": "info"},
    {"text": "交房租",     "state": "due"}
  ],
  "link": "/calendar"                     // 可选：点击分区跳转的目标路由
}
```

| 字段 | 类型 | 说明 |
|:--|:--|:--|
| `title` | string? | 分区标题；省略时视图用 manifest 的 `name` 兜底 |
| `items[].text` | string | **必填**。一行摘要（建议 ≤ 24 字，超出视图侧截断） |
| `items[].state` | string? | `info`（默认）/ `due`（待办/到期）/ `done`（已完成）/ `alert`（逾期/异常）—— 视图按 state 着色 |
| `items[].count` | number? | 聚合数字（如"习惯完成 3/5"），与 `text` 二选一或并存 |
| `link` | string? | 点击分区头部跳转的路由（如 `/calendar`） |

**上限建议**：`items` ≤ 5 条（视图只取前 5）；想给更多请聚合为一行（如"另有 7 条…"）。

## 4. 视图侧（Doubao）消费约定

1. 并发 GET 四家（calendar/todo/diary/review）；**每家独立 try/catch**（缺一不塌）
2. 404 → 分区显示「未安装」（灰态）；200 且 items 空 → 「今天还没有」；200 有 items → 渲染
3. 网络/5xx → 分区显示「暂时不可用」+ 重试按钮（**不当成"没数据"**）
4. 面板打开即取，**不轮询**（打开频率高，轮询是浪费 + 骚扰）

## 5. 各插件提供清单（v1 目标）

| 插件 | 数据源建议 | 归属 |
|:--|:--|:--|
| `calendar` | 今日事件列表（时间+标题） | calendar 属主 |
| `todo` | 今日到期 / 逾期（state: due/alert） | todo 属主 |
| `diary` | 今天是否已写（state: done/info） | diary 属主 |
| `review` | 今天是否已复盘 | review 属主 |

> 探测工具：`python tools/export_capability_map.py` 的 `summary` 段会列出**谁已实现**（U2 验收判据之一）。

## 6. 版本与演进

- v1 刻意**最小**：只覆盖"今日摘要"一种聚合。分组/周视图/自定义分区 → 候 v2（先让 v1 跑起来）
- 形状变更必须 bump `manifestVersion` 并在 changelog 记录（D′ 与提案 B 的既有纪律）

---

## 7. ★ 用户侧自定义（v1.1 补 · 主人「高度自定义化」要求）

**聚合面板的四个分区（calendar/todo/diary/review）由用户决定怎么摆** —— 视图侧底线四条：

| 项 | 要求 |
|:--|:--|
| **分区显隐** | 每个分区可单独隐藏（用户不用某个插件就不看它） |
| **分区排序** | 拖拽或上下移动改变顺序，顺序被记住 |
| **单分区条数** | 每区默认展示条数用户可调（默认 5） |
| **重置** | 必须有"恢复默认"入口 |

- **存储**：localStorage（与内核 `ui.*` 同钥匙族），**刷新与重进保持**
- **纪律**：自定义**只影响视图**，不改变服务端响应形状（BFF 仍原样透传，R-1 不变）
- **新增分区（新插件声明 x.summary.today 后）**：默认可见、排在末尾，用户可再调

**为什么写进规范**：否则每个视图各做一套（或干脆不做），主人就得忍受"固定四格"。
